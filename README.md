# Кандидатогенерация для поиска услуг Авито (Recall@50)

## Идея решения

Задача — для каждого запроса отобрать из корпуса (189 212 объявлений) до 50 кандидатов так,
чтобы в них попало как можно больше «выбранных» объявлений. Решение — классический каскад:

1. **Несколько дешёвых источников кандидатов** (по всему корпусу, плотными матрицами батчами запросов):
   * **BM25F** по стеммированным полям (заголовок ×3, параметры, описание) + **локационный приор**
     `log P(локация объявления | локация поиска)`, посчитанный по train. Локация — сильнейший сигнал:
     в train 83% выбранных объявлений из той же локации, что и поиск; BM25 без локации даёт 0.42, с локацией — 0.82;
   * **микрокатегорийный приор** `P(микрокатегория | запрос)`: kNN (TF-IDF слов + символьных n-грамм)
     по текстам запросов train и усреднение микрокатегорий выбранных по ним объявлений.
     Ловит запросы, чьи слова не встречаются в объявлении («очистка ног» → педикюр);
   * **история**: объявления, которые выбирали в train по похожим запросам;
   * **дообученные эмбеддинги** (bi-encoder `intfloat/multilingual-e5-small`, дообучен контрастивно
     на парах «запрос → выбранное объявление» из train, in-batch негативы) + локационный приор.
   Объединение топов источников — ~400–600 кандидатов на запрос.

2. **Ранжирование кандидатов LightGBM (lambdarank)** по ~35 признакам: BM25 по полям, покрытие
   слов запроса, локационный приор, расстояние до центра локации поиска, P(микрокатегория|запрос),
   совпадение фильтров поиска (`search_infm_params_text`) с параметрами объявления, популярность
   объявления, «удалённость» микрокатегории (доля кликов в чужой локации), косинус эмбеддингов,
   ранги внутри запроса, рейтинг/отзывы/цена и т.д. Берём топ-50 по скору модели.

## Валидация (без утечек)

Из train отложены два непересекающихся набора групп «запрос+локация+фильтры»:
* **val** — 2 500 запросов (для оценки), **rank** — 15 000 запросов (для обучения ранкера).
* Как в бенчмарке, по одной группе на текст запроса и ~37% текстов, встречающихся в остальном train.
* Корпус для них = `benchmark_items` + выбранные по этим запросам объявления.
* Все статистики (локационный приор, kNN, популярность) и дообучение эмбеддингов считаются
  **только по остальной части train** — метки val/rank нигде не используются.

| Вариант | val Recall@50 |
|---|---|
| BM25 (без локации) | 0.417 |
| BM25 + локационный приор | 0.817 |
| Кандидаты + LightGBM (без эмбеддингов) | 0.914 |
| Кандидаты + LightGBM + дообученные эмбеддинги | **0.936** |

## Как воспроизвести

Проще всего — открыть `solution.ipynb` и выполнить ячейки по порядку. Или вручную:

```bash
pip install -r requirements.txt
python prep.py                 # нормализация текстов, сплиты val/rank, корпуса      (~5 мин)
python train_emb.py            # дообучение e5-small (GPU ~25 мин; на CPU долго)
python encode_emb.py           # эмбеддинги объявлений и запросов
python features.py val         # кандидаты + признаки
python features.py rank
python features.py bench
python ranker.py eval          # Recall@50 на валидации
python ranker.py bench         # обучение финального ранкера, запись answer.csv
python check_answer.py         # проверка формата answer.csv
```
Данные лежат в `dataset/`, промежуточные файлы — в `work/`. Внешние API не используются;
веса e5-small один раз скачиваются с HuggingFace и дальше работают локально.

## Использованные open-source компоненты
* `intfloat/multilingual-e5-small` (MIT) — базовая модель эмбеддингов, дообучена на train;
* PyStemmer (Snowball, русский стеммер), scikit-learn (TF-IDF, CountVectorizer), SciPy (разреженные матрицы);
* LightGBM (lambdarank), PyTorch + HuggingFace Transformers, pandas/pyarrow.

## Файлы
* `prep.py` — подготовка данных и сплитов; `common.py` — BM25, метрика, загрузка сплитов;
* `train_emb.py`, `encode_emb.py` — дообучение и применение модели эмбеддингов;
* `features.py` — кандидатогенерация и признаки; `ranker.py` — LightGBM-ранжирование и `answer.csv`;
* `check_answer.py` — проверка формата; `exp_*.py` — эксперименты (бейзлайн, анализ промахов).
